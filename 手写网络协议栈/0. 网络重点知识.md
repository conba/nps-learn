# 网络重点知识

<img src="image\TCPIP协议族.png" style="zoom:50%;" />

1. **ARP**协议：**Address Resolve Protocol**, 地址解析协议，数据链路层协议
2. **RARP**协议：**Reverse Address Resolve Protocol**,逆向地址解析协议

以上协议实现了IP地址和机器物理地址（**通常是MAC，以太网，令牌环，802.11无线网络都使用MAC地址**）之间的相互转换

---

<img src="image\封装.png" style="zoom:50%;" />

3. 各层传输内容：**以太网帧（Ethernet frame），IP数据报(IP packet)，TCP报文段(TCP segment)，应用消息（Application message）**
4. 帧最大传输单元（**MAX Transmit Unit MTU**），即帧最多能携带多少上层协议数据（比如**IP**数据报）例如以太网帧的**MTU**是1500字节，正因为如此，过长的**IP**数据报可能需要分片（**fragment处理**）

| 目的物理地址 | 源物理地址 | 类型  | 数据        | CRC   |
| ------------ | ---------- | ----- | ----------- | ----- |
| 6字节        | 6字节      | 2字节 | 46~1500字节 | 4字节 |

5. **IPV4**协议头，长度通常为20字节，除非包含可变长度部分。16位总长度是指整个**IP**数据报的长度，以字节位单位，因此IP数据报的最大长度位**65535**（2^16-1）字节

<img src="image\IPV4协议头结构.png" style="zoom:50%;" />

6. 如果**MTU**是1500字节，那么IP数据报携带的数据部分最多为**1480**字节（**IP头部占用20字节**）
7. **TCP**协议的这种链接时一对一的，所以基于广播和多播（目标时多个主机地址）的应用程序不能使用**TCP**服务。而无连接的**UDP**则非常适合广播和多播

![](image\socket api 流程.png)

8. **listen()** 设置监听上限
9. 客户端程序一般不关心自己的IP和端口，不会使用**bind()**函数来绑定端口，而是使用系统随机分配的一个端口来通信
10. 服务器程序一般使用**INADDR_ANY**来监听电脑所有的网卡。

字节序转换

```c
// 字节序转换
#include <netinet/in.h>
unsigned long int htonl(unsigned long int hostlong);  // 32bit host to network long 用来转化ip地址
unsigned short int htons(unsigned int hostshort);     // 16bit host to net short 用来转化端口
unsigned long int ntohl(unsigned long int netlong);
unsigned short int ntohs(unsigned short int netshort);

#include <bits/socket.h>
struct sockaddr  // 通用socket 地址
{
    sa_family sa_family;
    char sa_data[14];
};

#include <sys/un.h>
struct sockaddr_un
{
    sa_family_t sin_family;  /*地址族，AF_UNIX*/
    char sun_path[108]; /*文件路径*/
};

#include <netinet/in.h>
struct sockaddr_in
{
  	sa_family_t sin_family;   /*地址族 AF_INET*/  
    u_int16_t sin_port;       /*端口号，要用网络字节序表示*/
    struct in_addr sin_addr;  /*IPV4地址结构，*/
};

struct in_addr
{
  	un_int32_t s_addr;      /*IPv4地址，使用网络字节序表示*/  
};
```

## 地址转换

```c
#include <arpa/inet.h>
in_addr_t inet_addr(const char* strptr);  // 将点分十进制的IPv4字符串转为网络字节序表示的IPv4地址，失败返回INADDR_NONE
int inet_aton(const char* cp, struct in_addr* inp); // 原理同上，不过将结果存储于inp指向的地址结构中
char* inet_ntoa(struct in_addr in); // 将网络字节序整数转为点分十进制

#include <arpa/inet.h>
inet inet_pton(int af, const char* src, void* dst);
const char* inet_ntop(int af, const void* src, char* dst. socklen_t cnt);
```



## 函数原型

```c
#include<sys/types.h>
#include<sys/socket.h>

// 创建一个套接字，socket 使用引用计数，fock时子进程会将引用计数+1
// domain: AF_INET, AF_INET6, AF_UNIX
// type: SOCK_STREAM, SOCK_DGRAM, type 参数可以接受SOCK_NONBLOCK和SOCK_CLOEXEC这两个的与&值，SOCK_BLOCK表示设置为非阻塞，SOCK_CLOEXEC表示在fock创建子进程时子进程中关闭该socket
// protocol: 0:tcp 
// ret success：返回sockfd -1: 查看errno
int socket(int domain, int type, int protocol);

// bind a name to a socket 给socket 绑定一个地址结构（IP + Port）
// struct sockaddr_in addr
// addr.sin_family = AF_INET;
// addr.sin_port = htons(8888);
// addr.sin_addr.s_addr = htonl(INADDR_ANY);
// addr: (struct sockaddr*)&addr;
// addrlen: sizeof(addr);
// 成功：0 ，失败：-1，errno
int bind(int sockfd, const struct sockaddr* addr, socklen_t addrlen);

// 设置同时与服务器链接的上限数（同时进行3次握手的客户端数量）
// backlog: 上限数值，最大值默认128
// 成功：0 失败：-1， 设置errno
int listen(int sockfd, int backlog);

// 从监听队列中取出已经建立链接的sockfd，如果没有，则阻塞等待客户端建立链接，成功的话，返回一个与客户端成功链接的sockfd
// int sockfd: 监听的sockfd
// struct sockaddr* addr: 传出参数，成功与服务器建立链接的socket的地址结构（IP + 端口）
// socklen_t * addrlen: 入， addr的大小，出：客户端addr的实际大小。
// ret success: 能与客户端进行通信的socket对应的文件描述符，失败：-1， errno
int accept(int sockfd, struct sockaddr* addr, socklen_t *addrlen);

// 主动链接服务器，不使用bind()绑定客户端的地址结构是可以的，系统会隐式绑定一个ip和端口。
// serv_addr: 服务器监听的socket的地址结构
// 成功：0 失败：-1， 设置errno
int connect(int sockfd, const struct sockaddr* serv_addr, socklen_t addrlen);

// 数据的读写，可以使用read()和write()来对socket进行读写，不过socket编程接口提供了几个专门用于socket读写的系统调用，其中用于TCP流数据读写的是recv()和send(), flags 通常设置为0

// buf：指定缓冲区的大小，len：指定缓冲区的长度
// recv > 0 成功时返回实际读取到的数据的长度，它可能小于我们期望的长度，因此可能需要多次recv，才能得到完整的数据
// recv = 0 对方已经关闭链接
// recv = -1 失败，并设置errno.
ssize_t recv(int sockfd, void * buf, size_t len, int flags);

// 往sockfd上写数据
// buf: 指定缓冲区的位置
// len：指定缓冲区的大小
// send >0 实际写入的数据的长度，=-1，失败，并写入errno
ssize_t send(int sockfd, const void *buf, size_t len, int flags);
```

Flags:

| 选项名        | 含义                                                         | send | recv |
| ------------- | ------------------------------------------------------------ | ---- | ---- |
| MSG_CONFIRM   | 指示数据链路层协议持续监听对方的回应，直到得到答复，它仅能用于**SOCK_DGRAM**和**SOCK_RAW**类型的socket | Y    | N    |
| MSG_DONTROUTE | 不查看路由表，直接将数据发送给本地局域网络内的主机，这表示发送者确切的知道目标主机就在本地网络上 | Y    | N    |
| MSG_DONTWAIT  | 对socket的此次操作将是非阻塞的                               | Y    | Y    |
| MSG_MORE      | 告诉内核应用程序还有更多的数据要发送，内核将超时等待新数据写入TCP发送缓冲区后一并发送，这样可防止TCP发送过多的小报文段，从而提高传输效率 | Y    | N    |
| MSG_WAITALL   | 该操作仅在读取到指定数量的字节后才返回                       | N    | Y    |
| MSG_PEEK      | 窥探读缓存中的数据，此次操作不会导致这些数据被清除           | N    | Y    |
| MSG_OOB       | 发送或接收紧急数据                                           | Y    | Y    |
| MSG_NOSIGNAL  | 往独断关闭的管道或者socket中写数据时不引发SIGPIPE信号        | Y    | N    |
